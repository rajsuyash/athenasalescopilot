## What changed since the first run

The first run flagged FIX REQUIRED for case #12 (caption pipeline). Investigation revealed:

**Root cause** — `prisma db push --accept-data-loss` reconciles the live DB against `schema.prisma`. The pgvector `embedding vector(256)` column was added by hand-rolled SQL only, NOT declared in the schema. So every api redeploy:
1. `prisma db push` DROPPED the column (to match schema)
2. `apply-manual-migrations.mjs` re-ADDED it (`ADD COLUMN IF NOT EXISTS`)
3. Existing rows came back with NULL embeddings → retrieval returned 0 chunks → coach fell to `askNext` early-return → no persistence

**Evidence** — `chunks_total=42, chunks_with_embedding=0` in prod Postgres. The first UAT only got grounded suggestions because the embeddings were still warm from initial seed; subsequent UATs after redeploy saw empty embeddings.

**Fix (76490b8):**
1. Declared `embedding Unsupported("vector(256)")?` on `KnowledgeChunk` in `schema.prisma` so db push leaves the column alone.
2. New `packages/db/scripts/backfill-embeddings.mjs` — re-embeds any NULL rows via OpenAI on api startup. Idempotent.
3. Wired into api startCommand: `prisma db push && manual-migrations && backfill-embeddings && start server`.

**Verification** — all 42 chunks now have embeddings. UAT case #12 PASS — 3 grounded suggestions in 11s, e.g. *"Compared to what, can I ask? Expensive versus where you are now, or versus where you want to be?"* (rationale references the objection-reframer playbook).
