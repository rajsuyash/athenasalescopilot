## Top 3 actions for next turn

1. **Investigate non-deterministic retrieval** — `services/realtime-gateway/src/lib/coach.ts:404-411` (early-return askNext when chunks empty) AND `services/api/src/modules/auth/service.ts` (signup auto-seed via `seedWorkspaceKnowledge`). The first UAT run for workspace `uat-prod-1777844720@athena.app` got chunks → 3 grounded suggestions. The second run for the SAME workspace got 0 chunks → 3 fallback ask_next responses → no persistence. Likely root cause: the fire-and-forget `seedWorkspaceKnowledge` is racing — it succeeded once but later requests hit before re-seeding. Fix: make seeding synchronous on first call OR add a guarded `ensureWorkspaceKnowledge` check before retrieval that triggers on-demand seed if vector index is empty for the workspace.
2. **Generate public domain for postcall service** — Currently recap is only reachable via the admin-web proxy (`/api/postcall/recap/<id>`). Direct access via `https://<api>/v1/meetings/<id>/recap` returns 404. This is fine if all clients are admin-web, but the chrome extension and any future clients won't have a way to fetch recaps. Decision: either (a) add a recap proxy route to api, or (b) generate a Railway public domain for `athena-postcall`.
3. **Auto-create vector index post-deploy** — `apply-manual-migrations.mjs` runs all 5 SQL files at api start, but the IVFFlat / HNSW index for `knowledge_chunks.embedding` is only created if the file lists it AND the table has rows at index time. Verify that `01_pgvector_chunk_embedding.sql` creates the index unconditionally (`IF NOT EXISTS`) so cold-start with empty data still indexes correctly.

### Group 1 — Caption pipeline non-deterministic on prod

**Affected cases:** #12
**Symptom:** Second run of `scripts/uat-pipeline.sh` against the same workspace produced 0 persisted suggestions despite 3 captions injected and routed correctly.
**Likely root cause:** Knowledge retrieval returns 0 chunks → coach early-returns `askNext` (line 411 in `coach.ts`) before persistence block. The same workspace had 3 chunks-grounded suggestions on the first run (case #10 confirms persisted data). Either knowledge is being purged between runs or the embedding cache/index is stale.
**Suggested fix:** See action #1 above.
